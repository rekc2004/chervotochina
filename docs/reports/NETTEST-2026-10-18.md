### 12.2 C20: причина и исправление (П1)

Цепочка причин [P] по коду, сверено с журналом [Ж]:
1. Смену внешнего IP своего NAT узел не видит. Снимок собственных адресов состоит из источника маршрута и адресов прослушивания (watch.rs:23-29), а частный адрес HA не меняется. Поэтому нет сброса наблюдений (own.rs:200-211), нет повторного стука, нет быстрого окна и нет нового ADDR_INFO (watch.rs:32-46).
2. Друзья с молчащим портом отбрасывают пакеты с нового внешнего адреса ещё до quinn (knock.rs:765-779). Миграции QUIC нет: все соединения HA умирают по простою через ~30 с [Ж: o1 на 38,8 с, наблюдатель на 41,2 с, смена была на ~8 с].
3. Наблюдатели переподключаются, по новому соединению приходит свежее наблюдение (engine.rs:517). Но наблюдение HB живёт ещё 1800 с (own.rs:16, :287-300), а HB сам за NAT и без токена не вернётся. Итог: nat_view=Conflicting с 43 с до конца строки [Ж], observed_v4 = None (own.rs:368-377), набор публикации пуст, токен даёт NoAddresses (addrinfo.rs:54-57). Единственный путь PR-PR, ручной токен, закрыт на 30 минут.
4. В первые ~30 с после смены nat_view ещё Eim. Три токена, выданные со статусом «ok», несли старый адрес [Ж].

Исправление (этап 16а, крит. схема; ревью security обязательно):
- **F1, обязательно: «текущие наблюдения».** `OwnAddrs::reporter_up(pair, now_unix)` вызывается после `live.insert` в on_connection. `reporter_down(pair)` вызывается везде, где снимается запись live: on_closed, вытеснение по max_live, cleanup_inactive, shutdown. Наблюдение считается текущим, если репортёр подключён и `obs.at >= up_since`. `live_v4` (через него nat_view, observed_v4, Symmetric, ManualForward) берёт только текущие наблюдения, если есть хотя бы одно; иначе все живые по TTL, как сейчас (ноутбук без связи ещё может выпустить токен с последним адресом). Решение 5 (друзья противоречат друг другу, адрес не рассылаем) сохраняется для одновременно подключённых друзей.
