# Сквозная проверка на двух настоящих компьютерах (2026-10-27)

Первая проверка продукта целиком, без подставных хранилищ и без петли: настоящий `chervo` (ветка `claude/angry-ritchie-a296d8`, 262d272, release) на двух машинах в одной домашней сети.

| | Узел A «Алиса» | Узел B «Боб» |
|---|---|---|
| Машина | рабочий ПК владельца, Windows 11 | Linux-машина владельца, Ubuntu (ядро 6.8) |
| Хранилище ключей | Диспетчер учётных данных Windows (настоящий профиль `%LOCALAPPDATA%\Chervotochina`) | gnome-keyring из .deb, распакован в домашний каталог (не установлен), изолированный `dbus-run-session`, временный HOME |
| Сборка | `cargo build -p chervo-cli --release --locked`, Rust 1.99.1 | то же, на самой машине |

## Шаги и результат
1. `chervo init --receive ПАПКА` на обеих. На Linux первая попытка с папкой 775 отвергнута: «Папка для приёма доступна другим пользователям…» — верное поведение. С правами 700 — принято.
2. B: `invite --lan` → токен `CHV1…` с предупреждением об IP. A: `accept-invite` + токен.
3. Проверочный код на обеих машинах одинаковый: `8385 3443`. `sas yes` с обеих сторон → «Друг добавлен.», «на связи (локальная сеть)». В Диспетчере учётных данных Windows появились `pair-v1-….chervotochina`, `friends-epoch-v1.chervotochina`, `friends-key-v1.chervotochina`.
4. **A → B:** папка `пакет/` (50 МБ случайных данных `большой.bin`, вложенная `вложено/мелкий.dat` 12 КБ, `записка.txt`). У B предложение с пометками «нужен вопрос о доверии» и предупреждением о программах; после «да» — «Передача завершена». **SHA-256 всех трёх файлов у B совпали с отправленными.**
5. **B → A:** `из-линукса.bin` 20 МБ случайных данных. **SHA-256 у A совпал** (`34fbb508…`).
6. `quit` на обеих: «снимаю проброс порта», «Узел остановлен». Повторный `chervo run` на обеих: друзья на месте, «на связи (локальная сеть)» без каких-либо действий.

## Найденные дефекты
- **D1 (интерфейс):** после завершённого приёма `transfers` у получателя показывает «приём Алиса: 1,0 МБ из 50,0 МБ. Передача завершена.», хотя все 50 МБ пришли и совпали. Счётчик байт получателя не доходит до итога. Отправитель показывает верно (50,0 из 50,0).
- Вопрос о доверии задан один раз на предложение с двумя помеченными файлами. Если по замыслу нужен вопрос на каждый файл — уточнить; иначе это не дефект.

## Не проверено
- Новое входящее соединение на Windows при включённом брандмауэре (здесь соединение начинала Windows-сторона, обратная передача шла по нему же).
- Интернет, NAT/CGNAT, UPnP на роутере, смена IP; поиск в LAN 13в (ветка не слита).
- macOS; GUI (ещё нет); установщик (этап 19).
- Ctrl+C на Windows; `recover accept-older/start-over` с настоящим хранилищем.

Тестовые данные остались: на Windows — профиль `%LOCALAPPDATA%\Chervotochina`, три записи в Диспетчере учётных данных, папка `%USERPROFILE%\chervo-e2e-recv`, `J:\chervo-e2e`; на Linux-машине — каталог `~/chervo-e2e` (исходники, сборка, распакованный gnome-keyring, временный HOME). Удаляются только по слову владельца.
