## Decisions (rationale)
1. **Name model.** An offered name is a relative path: UTF-8, components separated by `/` only, every entry is a regular file; directories exist only as prefixes of file paths (empty directories are not transferred; the wire is unchanged). Depth = number of components including the file (`a/b/c.txt` = 3). Links of any kind cannot be expressed on the wire [V: an entry is bytes plus a name, stage-14 X1].
2. **One portable sanitizer, same result on every OS.** The rules are the union of Windows, macOS and Linux restrictions, applied identically on all three, so the hostile table has one expected column and a name means the same thing for every friend. OS differences remain only in the filesystem and are handled by placement (decision 7).
3. **Two outcomes per name: `Hostile` or rewritten.** Structure that an honest chervo sender never produces (decision 12) makes the **whole offer** hostile: the policy declines it before the user sees it (`DECISION{Decline}`). Everything else a foreign filesystem might legitimately contain (reserved names, `:`, trailing dots, hidden names) is **rewritten** deterministically and flagged, never passed through. Rationale: a traversal attempt is proof of hostility; `CON.txt` from a Linux friend is not.
4. **Collision key without new packages (option A of Q1).** `fold(s)` = for each char `to_uppercase()`, then each result `to_lowercase()` (std tables, `char::UNICODE_VERSION` of Rust 1.99 [D]). Within one offer, names in the same directory with equal `fold` are resolved deterministically (decision 6). Unicode normalization: std has no tables; the lock has no normalization crate [P]. **Safety does not depend on tables:** every filesystem collision (APFS/HFS+ case and normalization folding, NTFS case folding and 8.3 aliases) makes `create_dir` / `hard_link` / `create_new` fail with `AlreadyExists`, and placement then picks the next free name. No table can match every filesystem anyway (NTFS uses a per-volume upcase table, HFS+ a frozen variant of NFD [D]). Residual under A: an NFC name and its NFD twin coexist on Windows/Linux as two files that look the same; NFD names from Mac senders stay NFD. Q1 asks whether to add NFC.
5. **Exact sanitizer** (`sanitize_path`, pure, no filesystem). Input `&str` (stage-14 `UntrustedName`: UTF-8, 1..=1024 bytes, no NUL). Checks in this order, first failure wins:
   - H1 empty -> `Empty`; bytes > `max_path_bytes` -> `TooLong`.
   - H2 any char in U+0000..=U+001F, U+007F, U+0080..=U+009F -> `Control`.
   - H3 any `\` -> `Backslash` (covers `C:\`, `\\server\share`, `\\?\`).
   - H4 starts with `/` -> `Absolute` (covers `//server/share`).
   - H5 first two chars are ASCII letter + `:` -> `Drive` (`C:/x`, `c:x`).
   - H6 split on `/`; count > `max_depth` -> `TooDeep`; any empty component -> `EmptyComponent` (`a//b`, `a/`).
   - H7 any component made only of `.` and space -> `DotComponent` (`.`, `..`, `...`, `. .`).
   Then each component is rewritten in this order (every step that changes something sets `changed`):
   - R1 char map to `_`: `< > : " | ? *`; look-alike separators U+2215, U+2044, U+FF0F, U+29F8, U+FF3C, U+29F5, U+29F9, U+FE68, U+FF1A, U+2236, U+A789, U+FE55, U+FE13; invisible and bidi controls U+00AD, U+034F, U+061C, U+115F, U+1160, U+17B4, U+17B5, U+180B..=U+180F, U+200B..=U+200F, U+202A..=U+202E, U+2060..=U+206F, U+3164, U+FE00..=U+FE0F, U+FEFF, U+FFA0, U+FFF0..=U+FFF8, U+1D173..=U+1D17A, U+E0000..=U+E0FFF (these also set `suspicious`). Exception: U+200D, U+FE0E, U+FE0F are kept when the previous char is in U+2600..=U+27BF or >= U+1F000 (emoji sequences).
   - R2 strip trailing `.` and space repeatedly; strip leading spaces.
   - R3 a leading `.` becomes `_` (no hidden files; `.chervo-partial` can never be offered).
   - R4 Windows devices: `stem` = text before the first `.`, trailing spaces removed; if ASCII-case-insensitively one of `CON PRN AUX NUL CONIN$ CONOUT$ CLOCK$ COM0..COM9 LPT0..LPT9 COM¹ COM² COM³ LPT¹ LPT² LPT³` (superscripts U+00B9, U+00B2, U+00B3), or the whole component is `desktop.ini` / `autorun.inf`, prefix `_`.
   - R5 every `~` followed by an ASCII digit becomes `_` (no 8.3 aliases like `PROGRA~1`).
   - R6 component > `max_name_bytes` (255): `split_ext` (below); the stem is cut at a char boundary so that stem + ext fits; trailing `.`/space of the cut stem removed (empty -> `_`); R4 once more.
   - R7 (only if Q1 = B) NFC.
   Invariants (checked by `is_portable_component`, asserted by tests and fuzz): non-empty; not only dots/spaces; none of the R1 chars, `/`, `\`, controls; no trailing `.`/space, no leading space or `.`; R4 stem not reserved; no `~digit`; <= 255 bytes; output path <= input bytes + depth; `sanitize(join(output)) == output` (idempotent). `split_ext(c)`: last `.` at position > 0 with 1..=32 bytes after it -> (stem, ".ext"), else (c, "").
6. **Offer plan** (`plan_offer`, pure). Files in index order are inserted into a tree; each directory holds a map `fold(name) -> node`. A directory component equal by `fold` to an existing **directory** merges into it (spelling of the first one wins); equal to a **file**, or a file equal to anything, gets the next free candidate `stem (k)ext` (files) or `name (k)` (directories), k = 2, 3, ... with a per-(directory, key) counter (O(n), bounded by `max_files`), stem cut so the result fits 255 bytes; sets `changed` and `renamed_in_offer`. Offer limits: `files.len() > max_files` -> `TooManyFiles`, sum of sizes > `max_total_bytes` -> `TooLarge` (both offer-level refusals like Hostile). `plan_offer_for_root` additionally computes, on Windows, the absolute length in UTF-16 units; > 259 sets `long_path` (warning only; std uses verbatim paths for long paths [D], test on CI).
7. **Placement layout.** The user chooses `root`; it is canonicalized once (`fs::canonicalize`; on Windows a `\\?\` verbatim path [D], so our names are created literally with no Win32 reinterpretation). `partial_dir = root/.chervo-partial` (same volume, so stage-14 hard link works; it cannot collide with offered names by R3); our journals in `root/.chervo-partial/receive/` (stage-14 sweep skips it: not 32 hex [P paths.rs:41-46, restore.rs:42]). **Top-level directories of an offer are always new**: at accept, for each top-level directory node, `create_dir(root/name)`, then `name (2)`, ... up to k = 999 (`AlreadyExists` -> next; existing user directories, symlinks and junctions are therefore never entered). Directories below are created by us inside our own tree. Top-level files go directly into `root`. Within our tree an existing real directory is ours and reused; anything else (file, symlink, junction) -> `Refused`.
8. **No-follow without `unsafe`, std only, all three OS.** Before each placement: every directory component from `root` down is checked with `symlink_metadata` (must be `is_dir()` and not `is_symlink()`; std reports Windows junctions as symlinks [D, test]); missing ones are created with `DirBuilder` (Unix `mode(0o700)`), then re-checked. The file is placed with stage-14 `place_no_clobber(temp, final)` (hard link or `create_new` + rename; both fail with `AlreadyExists` on an existing name, including a dangling symlink [D, test]). After placement the whole chain and `symlink_metadata(final).is_file()` are checked again; failure -> best-effort `remove_file(final)` and `Refused`. **Residual (stated, not closed):** a local process with write access inside `root` can swap a checked directory for a link between the check and the link call and back before the re-check; the file may then be created outside `root`. Rejected alternative: `openat`/`mkdirat`/`linkat` from `rustix 1.1.5` (in the lock [P], safe API, `at.rs:84, 205, 220`) closes it on Unix only; Windows has no std/safe equivalent; two code paths for an attacker who already writes into the user's folder. Mitigation: `root` and `partial_dir` must be private (decision 9). Revisit in stage 17.
9. **Root checks** (`ReceiveRoot::open`). Absolute, existing, real directory after canonicalize. `.chervo-partial` and `receive/` created (Unix mode 0o700) or, if present, must be real directories. Unix: our uid is learned std-only from `metadata().uid()` of a probe file we create in `.chervo-partial` (no `getuid` in std); `root` must be owned by it and `mode & 0o022 == 0`, `.chervo-partial` `mode & 0o077 == 0`; otherwise `RootError::Shared` / `PartialNotPrivate` unless `allow_shared_root` (default false). Windows: no ACL check without FFI (residual; user-profile folders are private by default [D]). Closes SECURITY-REVIEW-STAGE14 item 8 on Unix.
10. **Idempotence per (key, index) with two tiny journals, no names on disk.** `receive/<hex32>.dirs`: written once at `prepare` (tmp + `sync_all` + rename): magic `CHVRCVD1`, pair, id, `plan_digest` = SHA-256 of the sanitized top-level directory names in plan order (ring), count u32, k u16 per top-level directory, trailer SHA-256; <= 64 KiB. `receive/<hex32>.placed`: append-only 8-byte records `index u32, k u16, check u16` (`check = (index>>16) ^ (index & 0xFFFF) ^ k ^ 0xC4E7`), written (no fsync) **before** each candidate attempt; the last valid record per index wins, the first invalid record ends parsing. Replay: if the last record's candidate exists, is a regular file (`symlink_metadata`), has `size` and its root (recomputed with `chervo_transfer::{layout, block_len, leaf_hash, file_root}`) equals `f.root` -> `Ok` at that path; otherwise the candidate loop starts at k = 1 with **no** content comparison. So at most one full read per file per replay (no O(n²) reads by a friend sending many equal-size files) [V]. A lost record (crash before the OS wrote it) only yields a duplicate `name (2)`, never an overwrite. Trusted from disk: nothing (journals are checksummed, bound to the plan digest, k <= 999, names recomputed from the offer). Crash between `create_dir` and the `.dirs` write leaves an empty directory (residual).
11. **Stage-14 hooks (additive, default no-ops; the only change to `chervo-transfer`).** `Placement::prepare(&self, key: &TransferKey, files: &[OfferedFile]) -> Result<(), PlaceError>` and `Placement::forget(&self, key: &TransferKey)`. Called on a blocking thread: `prepare` in `accept_flow` right after `write_names_once` [P api.rs:592-595] (error -> existing `CANCEL{Limits}` / `Failed{Limits}` path [P api.rs:598-618] plus `remove_session` and `forget`); for restored sessions lazily before the first `place` of this process (`RecvSession.prepared: AtomicBool`; error -> handled as a `place` error, `prepared` stays false). `forget` after every `remove_session` whose key is known [P receiver.rs:999, restore.rs:68 only when the state decoded]. Also: `#[doc(hidden)] pub fn CompletedFile::new_for_test(..)` (today `pub(crate)` [P placement.rs:28]); `create_part_new` adds `#[cfg(unix)] OpenOptionsExt::mode(0o600)` [P paths.rs:180-185]. `GeneratedNames` stays test-only and is not used by stage 15 (its `disk_root` follows symlinks [P placement.rs:112-113], SECURITY-REVIEW-STAGE14 item 9).
12. **Sender side (for stage 18, provided here).** `portable_component(&str) -> Result<String, PathError>` (R1-R7 on one local component) and `plan_offer` are pub, so an honest sender offers already clean, collision-free names; the receiver re-sanitizes (idempotent) and sees `changed == false`. Hence `changed`/`suspicious` on the receiver mean "not an honest chervo sender or a bug" and block auto-accept.
13. **Never executable; marks of origin.** No `set_permissions`, no `PermissionsExt`, no `std::process`. Unix: `.part` is created 0o600 (decision 11), the hard link keeps it, directories 0o700, so no `x` bit ever (test `mode & 0o111 == 0`). **Windows Mark-of-the-Web on every received file** (`mark_of_the_web = true`): before linking, write the stream `<temp>:Zone.Identifier` = `[ZoneTransfer]\r\nZoneId=3\r\n` (std `File::create`; the ADS name is our constant, never from input; ADS belong to the file, so the hard link carries it [D, test]; only the main data stream of `.placing` is protected by stage-14 Rev. 4, it is not touched). Failure (FAT/exFAT, no ADS) is ignored. Effect: SmartScreen for programs, Office Protected View and macro blocking for documents [D, not testable here]. **macOS quarantine** (`quarantine = true`): `rustix::fs::fsetxattr` on the read-only opened temp, name `com.apple.quarantine`, value `0081;<8 lowercase hex unix seconds>;Chervotochina;` [D: format from memory], failure ignored; target-specific dependency `rustix = { version = "=1.1.5", default-features = false, features = ["std", "fs"] }` (in the lock [P Cargo.lock:1291], `fsetxattr` [P rustix src/fs/xattr.rs:154], feature `fs` [P Cargo.toml:97]). If this adds a `name =` line to the lock: drop quarantine, report (stop condition). Linux: no standard mark; nothing.
14. **Type classification** (`classify`, on the final sanitized component, ext = ASCII-lowercased `split_ext`, non-ASCII ext = Ordinary), one list on all OS; precedence Executable > DiskImage > ActiveDocument > Archive > Ordinary:

   - DiskImage (strong; mounting drops MotW [D]): iso img vhd vhdx dmg.
   - ActiveDocument: docm dotm xlsm xltm xlsb xlam pptm potm ppsm ppam sldm html htm mht mhtml xhtml.

RTL tricks are already neutralized by R1 (`photo<U+202E>gpj.exe` -> `photo_gpj.exe`, Executable, `suspicious`). Homoglyphs (`photo.ехе` in Cyrillic) are not programs on any OS -> Ordinary; the UI shows the real type separately (stage 18). 15. **Acceptance policy** `ReceivePolicy: AcceptPolicy` (sync, as the trait [P policy.rs:32-34]); it uses `plan_offer_for_root` (so `long_path` is known). Plan error -> `Decline` (counter `declined_hostile()` for the UI). `Permission::Ask` -> `Ask`. `AutoAccept(l)`: effective limits = componentwise min of `l` and `ReceiveConfig.auto_ceiling` (default 16 GiB, 1000 files); `Accept` only if every file is Ordinary, no `changed`, no `suspicious`, no `long_path`, and the friend's rolling 24 h usage plus this offer fits the effective limits (`AutoAcceptLimits` are read as "per 24 h"; one offer is bounded by the same numbers); usage is recorded at `Accept` (in memory, `Mutex<HashMap<PairId, VecDeque<(Instant, u64, u32)>>>`, pruned on each call; restart resets it) [V]; otherwise `Ask`. ## Do not
- No `unsafe`, no new package (except Q1 = B after the owner's answer), no `std::process`/`Command` in `src/`, no `set_permissions`, `PermissionsExt`, `create_dir_all`, `remove_dir_all`, `fs::copy`, `GeneratedNames`; nothing is opened by an app, executed or launched after receiving; no logging; no names or paths in `Debug`/`Display` of errors.
- Never write into an existing file; never enter a pre-existing directory of the user below `root`; never follow a link below `root`.
- No change of the wire format, the stage-14 state/names files, the friends file format.

## Untrusted input
Offered names (`sanitize_path`, `plan_offer`, bounded by 10 000 names / 2 MiB [stage 14]); the offered sizes (sum with `checked_add`); journals on disk (checksummed, bound, k <= 999); everything already in `root` (symlinks, junctions, short names, case twins: handled by `AlreadyExists` and the checks of decision 8).

## DoS bounds (authenticated hostile friend)

- **Нужно ваше решение:** на Windows свободное место без `unsafe` или нового пакета узнать нельзя, поэтому там автоприём пока всегда спрашивает. Варианты: A) добавить маленький пакет (например `fs4`); B) отдельный крейт с одним `unsafe`-вызовом; C) оставить вопрос на Windows. На Linux/macOS работает через уже имеющийся `rustix`.
- Исправлено по ревью: на Windows при подмене папки программа больше ничего не удаляет; расширения с необычными буквами (`ſ`, `ı`) считаются подозрительными и по ним тоже определяется программа; журнал запоминает подлинность папки; длина пути считается с запасом на « (k)».

## Rev. 4 addendum (owner decisions 2026-10-18, fix round 2)

1. **Free space via `fs4 = "=1.1.0"`** (workspace dependency, default features = sync; the only new `name =` in `Cargo.lock`; MIT OR Apache-2.0; its `rustix 1.1.5` and `windows-sys 0.61.2` were already in the lock). Replaces decision 5 of Rev. 3 on **all** OSes: `space::disk_space` = `fs4::statvfs(path)`, taking `available_space()` and `total_space()`; error or an OS other than unix/windows = `None` (unknown = Ask). Read in the fs4 1.1.0 source: **Windows** `available_space` = `lpFreeBytesAvailableToCaller` of `GetDiskFreeSpaceExW` (free to the current user, honours quotas; not the volume-wide free), `total_space` = clusters * cluster size from `GetDiskFreeSpaceW` (whole volume); **Unix** `available_space` = `f_bavail * f_frsize` (non-privileged users, not `f_bfree`), `total_space` = `f_blocks * f_frsize`, saturating. The `unsafe` lives inside fs4; our crates keep `unsafe_code = "forbid"`. `rustix` stays in `chervo-receive` for Unix only (macOS quarantine, `mark.rs`). Test `real_disk_space_probe` now expects `Some` on Windows too.
2. **Trust bypass closed in `chervo-friends`.** `TrustConfirmation` is defined in `chervo-friends` (`trust.rs`) and re-exported by `chervo-receive`. `FriendBook::set_permission` rejects any `Permission::AutoAccept(_)` with new `FriendsError::TrustRequired`; the only way to enable it is `FriendBook::enable_auto_accept(keys, pair, TrustConfirmation)` (writes limits `u64::MAX`/`u32::MAX`; file format unchanged). `Ask` still needs no token. `chervo_receive::enable_auto_accept` delegates to it. Residual: the token constructor is public, so this is an API-level guard against accidental or buggy paths, not against code that deliberately forges the confirmation. Tests: `autoaccept_requires_trust_confirmation` (friends), `duo` in `receive_net` asserts the direct call fails.
3. **Interface delta:** added `FriendsError::TrustRequired`, `FriendBook::enable_auto_accept`, `chervo_friends::TrustConfirmation`, dependency `fs4`; `set_permission(AutoAccept)` now errors (`InvalidLimits` for zero limits is no longer reachable through the book; it still guards the file codec).
4. **Для владельца:** на Windows свободное место теперь определяется (пакет `fs4`), автоприём там работает. Автоприём нельзя включить без подтверждения доверия даже прямым вызовом списка друзей. Остаток: конструктор подтверждения публичный, это защита от ошибок кода, а не от намеренной подделки.
