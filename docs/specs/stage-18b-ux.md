# SPEC 18б: правки интерфейса по ревью          критичность: КРИТИЧНЫЙ (разбор текста от друга, открытие папки)

Цель: обычный человек без знания сетей проходит путь «добавить друга → отправить → принять» без ложных ошибок и без жаргона; любой текст от друга вставляется в одно место.

Прочитать: `docs/reviews/REVIEW-GUI-UX.md` (разд. 2, 3, 4 — номера находок ниже оттуда), `docs/specs/stage-18-gui.md` (§4, §5 — правила окна), `docs/OWNER_DECISIONS.md` (последний раздел, решения 2026-11-18), `crates/chervo-gui/tests/*.rs` (стражи: `uses_node_api_only`, `gated_node_actions`, `code_scanner`, `no_fs_writes` и др.). Больше ничего не искать без нужды.

Решения владельца (2026-11-18): В2 — вариант (а), одна кнопка; Н7 — кнопка «Открыть папку» только для папки приёма, файлы не открываются.

Сделать:
1. **В1.** `Command::RefreshSnapshot` не порождает `Done(Err(Shutdown))`: в `worker.rs` ответ `None` для этой команды не превращается в ошибку (только новый снимок). «Узла нет» по-прежнему даёт ошибку для остальных команд. Тест: открыть «Настройки» при открытом узле → уведомлений нет.
2. **В2 + В3.** Одна точка вставки текста от друга.
   - Ядро (`chervo-core`, `Node`): новый метод, например `apply_friend_text(&self, text: &str) -> Result<FriendText, NodeError>`, который разбирает текст через публичный разбор `chervo-token` (вид по декодированному токену, а не по сравнению строк в окне) и вызывает существующий путь: приглашение → тот же путь, что `accept_invite` (дальше обязательная сверка кода, как сейчас); новый адрес → `apply_addr_update_text`; уведомление об удалении → `apply_revocation_text`. Проверки подписи, длины, версии — существующие, не ослаблять и не дублировать. `FriendText` сообщает окну, что произошло (например `InviteAccepted{..}` для перехода к сверке кода, `AddressUpdated{friend}`, `Revoked{friend}`).
   - Окно: на «Друзья» и на «Добавить друга» одна кнопка «Друг прислал мне текст» → поле → «Применить». Старые поля «Токен адреса друга» и вставки приглашения заменить этой кнопкой. Нераспознанный текст: «Это не похоже на текст из Червоточины. Попросите друга скопировать его целиком кнопкой „Копировать“.»
   - Если 18б и 13д расходятся: ошибка `InviteInAddrField` из 13д больше не нужна (общее поле); не добавлять её.
3. **В6.** Единые имена во всех текстах: `CHV1` — «приглашение», `CHA1` — «новый адрес», `CHR1` — «уведомление об удалении». Слова «токен» в пользовательских текстах нет.
4. **В7.** «Друг недоступен…»: назвать вероятные причины и кто что делает (по предложению ревью). «Приглашение принято» → «Связываемся с другом…».
5. **С3, С4, С5, С9** по предложениям ревью: ожидание после «Совпадает»; подпись «Как назвать друга в вашем списке»; «Пробуем соединиться…» после «Соединить»; «Действует до ЧЧ:ММ» у приглашения.
6. **Н4, Н5, Н6** по предложениям ревью (единицы размера одни на всё окно; пояснение к «(!)»; понятная фраза вместо «ссылки не разворачиваются»).
7. **Н7.** Кнопка «Открыть папку» на «Передачи» (и после приёма). Открывает только настроенную папку приёма из настроек (не путь от друга, не путь файла): проверить, что это существующий каталог; запуск системного проводника без оболочки: Windows `explorer.exe <путь>`, macOS `open <путь>`, Linux `xdg-open <путь>` через `std::process::Command` с одним аргументом, без `cmd /c`, `sh -c`, без склейки строк. Ошибку запуска показать текстом рядом с кнопкой. Если стражи GUI (`code_scanner` и т.п.) запрещают `process::Command` — сделать метод в ядре или узкое исключение в стражe только для этой функции, с тестом, что других вызовов нет; при сомнении — стоп и доклад.
8. **Формулировки.** Применить таблицу разд. 3 ревью ко всем строкам, кроме тех, что относятся к В4, В5, С8 (их делает 13д). Правило: каждый совет называет вкладку и кнопку («Друзья» → «Друг прислал мне текст»); без слов токен, NAT, UDP, SAS, LAN, пара, где человеку не нужно о них думать. Тексты ядра и окна согласовать между собой.

Интерфейс (точно): новый метод `Node` из п.2 и новый вариант команды окна для него; новая команда окна «открыть папку приёма». Остальной публичный API не менять. Метод п.2 добавить в список стражей `gated_node_actions`/`uses_node_api_only`, если они того требуют.

Не делать: не менять формат токенов, подписи, сверку кода, `chervo-token`, `chervo-connect`; не трогать В4, В5, С8, С1, С2, С6, С7, С10, С11, Н1–Н3, Н8–Н10, С12; не добавлять зависимости; не трогать `docs/specs/stage-13d-echo.md`, `docs/OWNER_DECISIONS.md`, release/ci.

Недоверенный ввод: текст из поля — от друга или из буфера, враждебный. Обрезать пробелы и переводы строк по краям; длина до существующего предела `chervo-token` до любого разбора; ошибки без паники; текст ошибки не повторяет вставленное. Путь папки — только из своих настроек.
