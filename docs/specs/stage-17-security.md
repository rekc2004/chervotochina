## 2. Decisions
1. **Logs = three checks, not a log grep of the product** (fact 1): (a) guard: no logger implementation crate (`env_logger`, `tracing-subscriber`, `simplelog`, `fern`, `log4rs`) in the normal dependency tree of product crates and no `log::`/`tracing::` macros in product `src/` (stage 18 may add a logger only with a new review); (b) **leak test over a full in-process scenario**: invite + SAS + connect + transfer + receive on loopback with a marker file name, collecting `format!("{:?}")` and `format!("{}")` of every event, error and returned value the public APIs produce; assert none contains the marker name, any IP literal of the run (`127.0.0.1`, the bound ports as `:port`), hex/base64 of any public or private key, PairId hex, SAS digits, token/invite/revocation text; (c) per-type unit tests for every sensitive type's `Debug`/`Display`. Stand logs are not product logs: they stay under the stand sanitizer, and the examples are excluded from release (stage 19).
2. **Rollback (T5):** a counter inside the file cannot detect restoring the whole old file [V]. Recommended (Q1 = A): a **security epoch** anchored outside the file, in the OS store (account `friends-epoch-v1`, 8-byte big-endian, not secret), bumped only by security-relevant changes (block, unblock, remove, rekey, applied peer revocation, new friend). Write order: file (epoch e+1) then store; on open `file < store` → `FriendsError::RolledBack` (the user decides: "the friends list is older than your last security change; check blocked/removed friends"; explicit `accept_older` sets store = file); `file > store` → repair store silently (crash between writes); store entry missing while file epoch > 0 → same as rolled back. Address seq rollback stays a residual (only wrong addresses, refusal; T5).
3. **Revocation durability:** never delete a pair key unless the revocation text is already persisted. New friend state `Retired { revocation: String, reason }` in plain v3 (v2 read and upgraded, v3 canonical): (1) sign, (2) save record as `Retired` with text, (3) delete key, (4) `forget_retired(pair)` after delivery or user dismissal. Save failure before (3) → `Io`, key kept, nothing deleted. Crash after (2) → on open, `Retired` with key present → delete key (idempotent). `Retired` is never in `kx_peers`, `usable_addrs`, dialing. Memory `unsent` removed.
4. **set_peers:** one `Mutex<()>` (`peers_update`) held across gate, knock and registry in `set_peers`; invariant test (see B2).
5. **Pre-auth slots:** `msg1_deadline` (default 3 s, clamped `<= auth_deadline`) from QUIC accept to a full msg1; `max_preauth_per_key` (default 2) unfinished connections per limiter key (IPv4 /32, IPv6 /64). Over limit or late: the existing uniform refusal path, nothing else on the wire.
6. **Process hardening:** `chervo_core::harden_process() -> HardenReport` (no error escapes; report lists what was applied): Linux `set_dumpable_behavior(NotDumpable)` + `RLIMIT_CORE = 0`; macOS `RLIMIT_CORE = 0`; Windows: nothing (residual, needs unsafe or a reviewed crate; WER LocalDumps off by default [D]). Called first thing in `chervo-cli` `main`; stage 18 GUI must call it before loading any key (requirement, guard test on `main.rs` text). Examples: not required.
7. **Fuzzing:** stable fuzz-smoke is the baseline in any case; add `CHERVO_FUZZ_SEED` (u64, default = current fixed seed) to every `fuzz_iters` helper so long runs use new seeds; add 3 targets (journal, SNTP, knock check: "random datagram of any length never admits"). libFuzzer only if Q2 = yes. "Corpus" for stable smoke = the list of seeds and iteration counts run (recorded in SECURITY_REVIEW), plus any crashing input saved to `fuzz/findings/<target>/` (synthetic data only).
8. **SBOM tool:** `cargo-cyclonedx` first choice (CycloneDX project tool [D]); fallback `cargo-sbom` [D]. Version, licence and flags [NP]: the builder verifies with `cargo search`/`cargo info` and `--help` of the pinned version before writing CI; licence must be in `deny.toml` allow-list style (MIT/Apache-2.0); if neither can be verified: stop.
9. **Supply chain CI:** pin `cargo-audit`, `cargo-deny`, SBOM tool with `--version =X.Y.Z --locked`; `cargo deny check` runs **all** sections (advisories, bans, licenses, sources); `deny.toml` gets `[advisories] ignore` mirroring audit.toml with `reason`, `[bans] multiple-versions = "warn"` and `deny = ["igd-next", "keyring", "keyutils"]` (stage 8 High; spec 10 decision 1; U10c item 2). Actions by SHA stay in stage 19 (TASK 19), except a **new** action added here (`actions/upload-artifact`) is pinned by SHA now [SHA NP: builder takes it from the release page and states the source].
10. **X02 flow (removes the stage 16 ambiguity):** verdict depends only on packets at victim `v`, never on who published. X02a (self-address lie): liar LW signs an address update listing `v` as its own address (patch point: the single expression in `crates/chervo-token/src/addr_flow.rs` / the update builder where LW's own addresses are taken; exactly one replacement or NOTRUN), connects to HA, disconnects; HA dials. X02b (observed-hint lie): patch the `observed` argument of `encode_addr_info` (`addr_flow.rs:56-60`) to `v`; LW is HA's only observer; WB connects to HA afterwards. Both: victim counts packets for 300 s. PASS: bursts spaced ≥ 30 s and ≤ 11 bursts; 0 bursts = PASS with note (e.g. `Conflicting`, nothing published). Closer spacing = FAIL to security.
11. **Review structure:** S1 full review (opus/high) by area A1-A7 (sec. 5); S2 **independent** second review (opus/high, fresh context, not the author of any reviewed code, does not receive S1's findings until its own list is returned) of A1, A2 and all stage 17 code. Disagreement on severity: the higher holds until the conductor/owner decides. The conductor writes `docs/SECURITY_REVIEW.md` from the reviewers' words (reviewers only read).
