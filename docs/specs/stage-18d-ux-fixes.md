# SPEC 18д: правки по живой проверке с ноутбуком          критичность: КРИТИЧНЫЙ (п.1 — папка приёма), остальное обычное

Источник: живая проверка 2026-11-20 (два компьютера в одной сети, GUI на одном, CLI на другом). Разведка с местами в коде: отчёт scout в этом же разговоре, ссылки ниже. Решения владельца 2026-11-20 записаны в `docs/OWNER_DECISIONS.md` (раздел «18д»).

Исполнитель: `combine-builder`, Sonnet, effort **high** (п.1 трогает ядро и путь приёма). После — `combine-security` по п.1 и п.3.

## 1. Новая папка приёма действует сразу (КРИТИЧНО)
Сейчас: `Node::set_receive_root` (`crates/chervo-core/src/node/transfers.rs:289-300`) проверяет папку (`ReceiveRoot::open`) и пишет настройки, но живой корень `self.core.root` не меняется (читается в transfers.rs:128, 139, 167, 184); `settings().restart_needed` (transfers.rs:345-348) включает `receive_root`; GUI показывает `texts.rs:325-326` «вступит в силу после перезапуска».

Нужно:
- Живой корень делается заменяемым: например `core.root: Mutex<Arc<ReceiveRoot>>` (или RwLock), читатели берут клон `Arc` один раз на операцию. Открытие нового корня — тот же `ReceiveRoot::open` с теми же проверками (ничего в проверках не ослаблять, `allow_shared_root` как сейчас).
- Порядок: открыть новый корень → сохранить настройки → подменить живой корень. Если сохранение не удалось — корень не подменяется (как сейчас: ошибка пользователю).
- Передачи, уже принятые в старую папку (идущие), продолжают писать туда (держат свой `Arc`), ничего не переносится. Новые предложения и `accept` — в новую папку. Прежняя основная остаётся среди дополнительных (`settings::replace_root` уже так делает) — и это должно действовать сразу же для `accept --into`/«Выбрать другую папку», если там тоже живой список.
- `restart_needed` больше не учитывает `receive_root` (`live.receive_root` обновлять при подмене). Текст «вступит в силу после перезапуска» для папки убрать; после успешной смены GUI пишет «Папка приёма изменена.» (без перезапуска).
- Тесты (ядро): смена корня → следующий приём ложится в новую папку без перезапуска; идущая передача в старую папку завершается в старой; неудачная смена (папка не открывается / сохранение не удалось) оставляет старый корень; `restart_needed == false` после смены папки.

## 2. Уведомления в шапке не врут
Сейчас: `Model::push_notice` (`crates/chervo-gui/src/main_model.rs:222-230`) копит строки, снимает только «Скрыть» (`MainIntent::DismissNotices`, main_model.rs:464-466). Строки о друге приходят из `settings_model.rs:379-393` (NEED_TOKEN_TEXT, LAN_EXPIRED_HINT). Событие «друг снова на связи» GUI не обрабатывает. Это отложенный пункт аудита С2 (`docs/reviews/REVIEW-GUI-UX.md:37,138`).

Нужно:
- Уведомление хранит необязательную привязку: `friend: Option<Id>` и/или вид (`kind`), не только текст.
- Когда друг становится доступен (на связи / соединение установлено — найти существующее событие или поле снимка `online`), все уведомления, привязанные к этому другу, снимаются сами.
- Уведомления о действии, которое пользователь уже завершил, не копятся: «Папка лежит вне вашего профиля…» после подтверждения галочкой снимается; «Папка приёма изменена.» снимается через ~10 с или при следующем действии в настройках (на выбор builder, описать).
- У каждой строки свой крестик «×» (убрать одну); общая «Скрыть» остаётся как «Скрыть все».
- Тесты модели: уведомление друга снимается при `online`; крестик убирает одну строку; общий сброс — все.

## 3. Подпись для `.bin` и других «может быть программой» (решение владельца)
Класс `.bin` не меняется (`crates/chervo-receive/src/classify.rs:122`, Executable; вопрос и галочка остаются). Меняется только подпись: `texts.rs:299` «программа или опасный тип» → «может оказаться программой». Оранжевое предупреждение над кнопками — тоже мягче и точнее: «Среди файлов есть такие, которые могут оказаться программами. Принимайте их, только если ждёте их от этого друга.» Тест на жаргон соблюдать. `chervo-receive` не трогать.

## 4. Надпись о месте на диске
Формула не меняется (`crates/chervo-receive/src/space.rs:57-61`: размер + `min_free_percent` от объёма тома; решение этапа 15). Меняется только текст (`crates/chervo-gui/src/texts.rs:561-566` и место вывода в offers.rs): показать размер файлов и сколько останется после приёма, и правило отдельно. Пример: «Размер: 512,0 МБ. Свободно 75,3 ГБ, после приёма останется 74,8 ГБ. Программа не заполняет диск дальше, чем до 10% свободного места.» Когда места не хватает — то же, плюс понятная причина. Числа брать из тех же данных, что сейчас.

## 5. «Готовим файлы к отправке…» сменяется на отправку
`TEntry.preparing` (ядро `core.rs:212-215`) не сбрасывается событием прогресса передачи (`core.rs` ~206-211). Нужно: первое событие прогресса передачи данных (или начало передачи) сбрасывает `preparing` (как `finished()` на core.rs:159). GUI (`screens/transfers.rs:72-76`) и CLI (`repl.rs:690-693`) после этого сами показывают обычный прогресс. Тест ядра: после Preparing → Progress поле `preparing` пустое.

## 6. Очистка списка «Передачи» (решение владельца)
В ядре нет удаления записи (лимит 256, `core.rs:33, 88-103`). Нужно:
- Ядро: `Node::forget_transfer(id)` — убирает из списка только завершённую запись (завершена / отменена / отклонена / ошибка); для идущей или ожидающей — ошибка, ничего не меняется. `Node::forget_finished()` — убирает все завершённые. Файлы на диске не трогаются никогда.
- GUI: у каждой завершённой передачи кнопка «Убрать» (без «?» не обязательно — обычная, с подсказкой «?» как у всех); над списком «Очистить завершённые» (видна, если есть завершённые). Намерения строятся в `src/screens/` (страж `user_intents_are_built_only_on_screens`).
- CLI: команды `forget N` и `forget-done` (помощь `help` дополнить).
- Тесты: ядро (идущую убрать нельзя; завершённую можно; файл на диске остался), GUI-модель.
