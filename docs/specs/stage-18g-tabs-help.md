# SPEC 18г: три вкладки и значок «?» у каждого пункта          критичность: обычный

Решения владельца (2026-11-19):
- вкладки главного окна свести в три: **Друзья / Файлы / Настройки**;
- значок «?» с всплывающим описанием у каждого пункта внутри вкладок (кнопка, галочка, поле ввода, переключатель), кроме очевидных: «Копировать», «Отмена», «Закрыть», «Назад», «Да»/«Нет» в вопросах подтверждения.

Исполнитель: `combine-builder`, Sonnet, effort medium. Сеть, ядро, криптография, файлы не трогаются: меняется только крейт `chervo-gui`.

## 1. Вкладки

Сейчас `enum Page` (`crates/chervo-gui/src/model.rs:288`): Friends, AddFriend, Send, Offers, Transfers, Diagnosis, Settings. Панель: `src/screens/placeholder.rs:13-19` (`PAGES`), выбор экрана `placeholder.rs:63-69`.

Станет:
| Вкладка | `Page` | Что внутри, сверху вниз |
|---|---|---|
| Друзья (`NAV_FRIENDS`) | `Friends` | список друзей (нынешний friends.rs); под ним раздел «Добавить друга» (нынешний add_friend.rs) — сворачиваемый (`egui::CollapsingHeader`), свёрнут, если друзья есть, и развёрнут, если список пуст |
| Файлы (новая `NAV_FILES = "Файлы"`) | `Files` | раздел «Входящие» (offers.rs) — показывается, только если есть ожидающие предложения; затем «Отправить» (send.rs); затем «Передачи» (transfers.rs). Счётчик ожидающих входящих переезжает на ярлык вкладки: `Файлы (N)` при N>0 |
| Настройки (`NAV_SETTINGS`) | `Settings` | нынешние настройки (settings.rs, включая раздел «Обновления»), затем раздел «Диагностика» (diagnosis.rs) |

- Разделы внутри вкладки разделяются заголовком раздела (`ui.heading` или `CollapsingHeader`) — заголовки берут старые названия: «Добавить друга», «Входящие», «Отправить», «Передачи», «Диагностика».
- Вкладка прокручивается (`ScrollArea::vertical`), если содержимое длинное.
- Варианты `AddFriend`, `Send`, `Offers`, `Transfers`, `Diagnosis` убрать из `Page`. Программные переходы (список ниже) ведут на новую вкладку и, где был переход к разделу, разворачивают/прокручивают его (`scroll_to_me` по флагу в модели, флаг сбрасывается после одного кадра). Места: main_model.rs:456, :600, :764, :811, :868; placeholder.rs:50; friends.rs:52, :108, :218; send.rs:78; settings.rs:400; model.rs:531-537 (обновление снимка при переходе на Settings — сохранить; если диагностика при открытии что-то обновляла, сохранить это для Settings).
- Помощник «Входящие подключения» (access.rs) остаётся как сейчас: заменяет содержимое вкладки, пока открыт.
- Файлы экранов в `src/screens/` не переименовывать и не переносить в другие модули (на расположение завязаны тесты `tests/gated_node_actions.rs`, `tests/update_gates.rs`, `tests/ui_thread.rs`). Функции экранов вызываются из новой вкладки как разделы.
- Тест `placeholder.rs` `no_updates_tab` переписать: вкладок ровно три, NAV_UPDATES среди них нет.

## 2. Тексты, которые называют вкладки
В `texts.rs` подсказки и сообщения называют старые вкладки («перейдите во вкладку Передачи» и т. п., ~25 строк: grep по «Добавить друга», «Отправить», «Входящие», «Передачи», «Диагностика», «Обновления»). Каждое такое указание переписать на новый путь: «Друзья → Добавить друга», «Файлы → Передачи», «Настройки → Диагностика» и т. д. Где название — это имя кнопки, а не вкладки (например «Отправить» на кнопке), не трогать.
- Расширить `texts_name_tab_and_button`: тексты, которые называют вкладку, должны начинаться путь с одного из трёх названий вкладок; добавить проверку, что ни один текст подсказок не ссылается на старую вкладку как на вкладку (фразы «вкладк… Передачи/Отправить/Входящие/Диагностика/Добавить друга»).
- Простые слова, без жаргона (действующий тест на жаргон соблюдать).

## 3. Значок «?»
- Использовать только `help_mark` / `label_with_help` из `screens/common.rs`. Для кнопки и галочки: `ui.horizontal(|ui| { кнопка; help_mark(ui, TEXT) })`. Можно добавить в common.rs помощники `button_with_help(ui, label, help) -> Response` и `checkbox_with_help(...)`, если это убирает повтор; намерения (`Intent`) по-прежнему создаются в файлах `screens/` (страж `user_intents_are_built_only_on_screens`).
- Каждый текст пояснения — константа в `texts.rs` с префиксом `HELP_`. 1–3 коротких предложения: что делает пункт и когда его нажимать. Простыми словами, без слов из списка жаргона.
- Существующие длинные пояснительные подписи под пунктами (не предупреждения) убрать под «?». Предупреждения безопасности (`IP_WARNING`, вопрос о роутере, оранжевые `warn`) остаются видимыми.
- Охват: все экраны вкладок и разделов (friends, add_friend, send, offers, transfers, diagnosis, settings, update::section, access, start). Окно закрытия и вопросы подтверждения — нет.
- Тест в `texts.rs`: все `HELP_*` непустые, не длиннее 300 символов, без жаргона. Тест (source-scan, как в tests/*.rs) по `src/screens/*.rs`: число вызовов `help_mark`/`label_with_help`/`*_with_help` не меньше числа `ui.button(`/`ui.checkbox(`/`ui.radio_value(`/`TextEdit` за вычетом явно помеченных исключений (комментарий `// без ?: очевидная` в той же строке). Простая эвристика допустима; описать её в отчёте.
