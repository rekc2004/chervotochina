# Ревью безопасности спецификации этапа 10 (combine-security, Opus/high)

Читал: `docs/specs/stage-10.md`, BRIEF (разд. 2, 3, 7), OPEN_QUESTIONS U10, OWNER_DECISIONS, `crates/chervo-identity/*`, `deny.toml`, `ci.yml`, `check-forbidden.sh`. Кода этапа нет. **Все утверждения об API крейтов взяты из памяти и по исходникам не сверены [НП]**: в среде нет cargo/rustc и реестра. Отчёт сохранён как есть (агент-рецензент), содержание не проверено дирижёром.

1. **High.** stage-10.md:18,103 против BRIEF.md:22. Требование «не попадает в бэкапы» понижено до «записать [НП]», хотя владелец этого не решал. Хранилища ОС лежат файлами в профиле пользователя и уходят в файловые бэкапы: Credential Manager (DPAPI), login keychain, login.keyring у Secret Service [В/НП]. Любой процесс того же пользователя может прочитать ключ без запроса (Windows, разблокированный Secret Service) [НП]. Правка: стоп-пункт «вопрос владельцу U10a: принять остаточный риск или иное»; требование BRIEF 3 выполненным не считать; сценарий «кража ноутбука / бэкап / вредонос под тем же пользователем» записать в THREAT_MODEL.
2. **High.** stage-10.md:20,110. Подмена хранилища: в keyring 3.x без платформенных фич работает mock-хранилище в памяти [НП для 4.x]. Стоп-условие говорит о подмене только для Linux. Правка: распространить на все ОС; `OsKeyStore` явно создаёт конкретное платформенное хранилище, а не сборщик по умолчанию; в шаг 3в добавить `cargo tree -e features -i keyring`; в ручном тесте проверять сохранность через новый экземпляр `OsKeyStore`.
3. **Medium.** stage-10.md:17. Если в keyring/secret-service не включено шифрование, сессия D-Bus может идти открытым текстом [НП]. Правка: в 3в вопрос «шифруется ли сессия», требовать чисто-Rust криптографию сессии; только через openssl это СТОП.
4. **Medium.** stage-10.md:70. Ключ может молча смениться: хранилище ошибочно вернуло «записи нет» (заблокировано, другая коллекция, очищено), и `load_or_create` создаёт новый ключ; два процесса одновременно получают None и оба пишут. Правка: разделить на `load(&S) -> Result<Option<DeviceKey>>` и явный `create(&S)`, либо передавать ожидаемый `DeviceId` из несекретной конфигурации и возвращать KeyMissing; записать требование одного экземпляра процесса.
5. **Medium.** stage-10.md:27-28. Нет контроля целостности записи: любые 32 байта валидный seed, испорченная запись даёт другой ключ без ошибки. Правка: формат `[ver][seed32][pub32]` (65 байт), при загрузке сверять публичный ключ, при несовпадении `CorruptKey`, негативный тест.
6. **Medium.** stage-10.md:31,34,66. Не сказано, что `verify` сам разбирает ключ и проверяет `is_weak`; `DeviceId::from_bytes` (непроверяющий) остаётся публичным. Неканонические кодировки (y ≥ p) могут приниматься [НП], тогда один ключ получает два `DeviceId`, ломается пиннинг и список друзей. Правка: `try_from_slice` и `verify`: разбор, `is_weak`, сравнение `to_bytes() == input`, иначе `InvalidPublicKey`; тесты на слабый ключ и неканоническую кодировку (векторы ed25519-speccheck [НП]); переименовать в `from_bytes_unchecked`.
7. **Medium.** stage-10.md:38,43,70. Пробелы в обнулении: seed из blob через `try_into` оседает во временном `[u8;32]`; blob через `push` может переаллоцироваться, старый буфер не обнуляется. Правка: `Zeroizing<[u8;32]>` с `copy_from_slice`, `Zeroizing<[u8;KEY_BLOB_LEN]>` (или `vec![0;N]` нужной длины); в 3а проверка обнуления `ExpandedSecretKey` в `sign` [НП]. Тест `secret_types_zeroize_on_drop` тавтологичен (маркер ставится вручную), это не доказательство: так и записать.
8. **Medium.** stage-10.md:40. `sign` подписывает произвольные байты без разделения доменов, а один ключ пойдёт на токены, обновления адреса и TLS RPK (DECISION.md:51): возможна межпротокольная подмена. Правка: `sign(domain: SignDomain, msg)` с фиксированной меткой-префиксом и такой же `verify`. Интерфейс фиксируется сейчас, позже менять дороже.
9. **Medium.** stage-10.md:80,83. Тест `src_has_no_filesystem_io` обходится: `use std::{fmt, fs}`, `print!`, `stdout`/`stderr`, `log`/`tracing`, `process::Command`. Запрет `unwrap`/`expect`/индексации (строка 80) ничем не проверяется. Правка: в lib.rs `#![deny(clippy::unwrap_used, clippy::expect_used, clippy::indexing_slicing, clippy::panic)]`; в grep `\bfs\b` и перечисленные шаблоны; альтернатива `disallowed-methods` в clippy.toml [НП].
10. **Medium/low.** stage-10.md:87. Тест no_disk почти пустой: `MemoryKeyStore` на диск не пишет, а реальный риск (бэкенды keyring) не покрыт. Сканер не ищет base64 (std/url, с паддингом и без) и 33-байтный blob. Правка: добавить шаблоны; в «НЕ проверяется» записать, что тест покрывает только путь через память.
11. **Low.** stage-10.md:85. Ручной тест с хранилищем ОС: `delete` в Drop-guard (при панике тестовый ключ останется в ключнице, возможно в iCloud); запретить тестам трогать `DEFAULT_SERVICE`/`DEFAULT_ACCOUNT`; запускать только после ответа на U10.
12. **Low.** stage-10.md:21,97-98. Добавить критерий `cargo tree -p chervo-identity -e features -i ed25519-dalek`: только std, zeroize, fast. Требовать ed25519-dalek ≥ 2 (в 1.x RUSTSEC-2022-0093). «cargo audit не запускался» допустимо для критичного этапа только при зелёном supply-chain job в CI.
13. **Low.** stage-10.md:80-84 против BRIEF.md:76 (фаззинг, злые входные). Без новых зависимостей перебрать длины 0..=70 и все 256 значений байта версии: нет паники, ошибка правильная.
14. **Low.** stage-10.md:36,51. Для `DeviceKey` запретить PartialEq/Hash/AsRef/Deref/serde. `MemoryKeyStore` публичен в рабочем API: при случайном использовании устройство получает новую идентичность на каждом запуске. Правка: пометить «только для тестов» или вынести под фичу.
15. **Low (процесс).** stage-10.md:3 против PLAN_DRAFT.md:19, TASK.md:42 («ведёт architect, не builder») и OWNER_DECISIONS.md:20 (сначала ревью architect, затем security). В спецификации нет шага ревью architect.

**Не проверено:** исходники ed25519-dalek, getrandom, zeroize, keyring 4.x (нет реестра, cargo/rustc); ZeroizeOnDrop у SigningKey и ExpandedSecretKey; поведение `verify_strict` на слабых ключах; приём неканонических ключей; mock-подмена в keyring 4; значение Persist на Windows; kSecAttrSynchronizable на macOS; шифрование сессии Secret Service; лицензии будущих зависимостей против deny.toml; clippy.toml на уровне крейта; THREAT_MODEL.md отсутствует.
