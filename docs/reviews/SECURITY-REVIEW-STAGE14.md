# Ревью безопасности этапа 14 (передача)

Автор: combine-security (opus/high), 2026-10-17. Diff `2a5e0dd..3efa281`. Опоры: `docs/specs/stage-14-transfer.md`, `docs/OWNER_DECISIONS.md`, `docs/THREAT_MODEL.md`, ревью 13 и 13а. Записано дирижёром со слов ревьюера (агент только читает).

## Итог
Critical и High нет. Друг не может подсунуть другие байты, получить файл под итоговым именем до полной проверки или превратить недоверенное имя в путь. 2 Medium, остальные Low.

## Находки
1. **Medium.** Файл состояния целиком переписывается на каждое событие файла; объём записи не ограничен принятым размером (`receiver.rs:332-340` `persist`, вызовы `receiver.rs:486-489`, `writer.rs:382, 408`, `receiver.rs:380`). 10 000 пустых файлов с именами на ~2 МиБ: ~20 тыс. fsync и ~48 ГиБ записи на передачу 0 Б; честная папка 10 тыс. фото ~28 ГБ. Мера: имена один раз при принятии в отдельный неизменяемый файл с контрольной суммой; в `state` только компактные статусы; объединять запись через таймер контрольной точки (флаг «грязно»).
2. **Medium-Low.** После жёсткой ссылки `.part` и размещённый файл — один файл (`placement.rs:370-374`): если удаление временного не удалось (Windows PermissionDenied) или сбой между link и unlink, `.part` остаётся (`receiver.rs:375-376`); позже `prepare` со сменой root игнорирует ошибку удаления (`receiver.rs:524-526`, `paths.rs:185`), `open_part_write` без truncate (`paths.rs:161`) пишет новые блоки в уже объявленный файл. Мера: после успешного `hard_link` — `Ok(HardLink)`, удаление best effort; в `prepare` неудачное удаление `.part` — пауза; новые `.part` через `create_new`.
3. **Low-Medium.** Один злой друг останавливает передачи всех: бюджеты памяти общие (`shared.rs:550-551`), таймер 60 с сбрасывается на каждом байте (`wire_io.rs:85-104`); отправитель по 1 байту < 60 с держит весь бюджет 128 МиБ, остальные ждут в `acquire_many_owned` (`rstream.rs:263`); зеркально на отправке (`sender.rs:918-969`). Мера: доля бюджета на передачу и/или общий срок на блок.
4. **Low.** GET_MANIFEST без предела (`sender.rs:854-875`): ~9 байт запроса -> до 2 МиБ ответа, буфер вне `send_budget`. Мера: счёт выдач на файл, буфер под бюджет.
5. **Low.** `max_data_streams` ограничивает одновременные потоки попытки, не сумму за сеанс (`sender.rs:776-780`); фактически ограничено 60 потоками/мин движка.
6. **Low.** Передачи на паузе занимают `max_inbound_active` до `partial_ttl` 7 дней (`api.rs:292-298`). Мера: считать только Active или показывать и истекать.
7. **Low.** Память вне бюджетов (буферы манифеста `rstream.rs:449`, списки хэшей) ~16-32 МиБ на передачу — ограничено; в T2.
8. **Low (только локальный атакующий).** Файлы в `partial_dir/<hex>` открываются со следованием симлинкам (`paths.rs:117, 161`); контрольная сумма состояния без ключа — вредонос может поставить Placed (`restore.rs:75`). Мера: `partial_dir` личный для пользователя; в T4.
9. **Сведения.** `writer.rs:376` всегда истина (настоящая проверка — `verify_after_write`, публичный флаг: запретить `false` вне тестов). `GeneratedNames` публичен, `disk_root` следует симлинкам (`placement.rs:328-338`) — этап 15 не должен его использовать. Hold берётся отдельно от `conn` (`receiver.rs:790`) — безвредно.

## Проверено, верно
Кодек (точные длины, хвосты отвергаются, длина кадра до выделения `wire_io.rs:66-74`), сборка предложения (checked_add, точные суммы), порядок проверок (BLOCK.len до чтения `rstream.rs:382`, раскладка из размера до списка хэшей `rstream.rs:443`, список хэшей воспроизводит root), схема хэшей, перехэширование с диска перед размещением, пределы перекачки 3/64, файл состояния (предел длины, контрольная сумма, раскладка, ≤ 8 InProgress, `.hashes` воспроизводит root, root подтверждается новым MANIFEST, пара == `remote_pair`), имена и пути (`untrusted_str` только в кодеке и состоянии, пути только в `paths.rs`/`placement.rs`, каталоги сеансов hex, уборка через `symlink_metadata`), BIND, диспетчер, hold vs `max_live` (превышение ≤ ~8 пар), окно quinn 16 МиБ после аутентификации / 64 КиБ до, FileStore только в примере, `stage14.sh` только `chv14-*`.

## Не проверено
`transfer_net`, fuzz 1M, clippy, netns; поведение памяти quinn вне чтения кода; `rename`/`hard_link` на FAT, сетевых дисках, NTFS; `events.rs`, `texts.rs`, `policy.rs`, тестовые подделки, весь `node14.rs`; два известных открытых пункта.
