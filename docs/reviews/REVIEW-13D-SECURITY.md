# Ревью безопасности 13д (коммиты 3ba061b, bae1830; combine-security, 2026-11-18)

Critical и High нет. Ниже находки и решение дирижёра.

## К исправлению (круг 1)
1. **Medium. Отзыв согласия не останавливает поддержание адреса.** `crates/chervo-core/src/node/echo.rs` (`set_echo_server`, около строк 464-481) сбрасывает только `probe.last`; уже запущенные `keepalive_loop` (около 747-784) продолжают раз в 25 с слать запросы на старый сервер до SAS, отмены или срока приглашения (до 86400 с). Нарушает Р9 («без сохранённого сервера ни одного пакета»). Исправить: при `set_echo_server(None)` и при смене сервера остановить все поддержания (забрать `echo.keepalives`, разбудить каждое, чтобы цикл завершился). Тест: после `set_echo_server(None)` к серверу не приходит ни одного пакета (сервер из dev-dependency считает запросы).
2. **Medium. Ложный «точный адрес роутера».** `network.rs` (около 116-118) пишет `last_identify` сразу после `identify`, до ответа «Разрешить»/«Не разрешать», и никогда не сбрасывает; `url.rs` проверяет только совпадение хоста LOCATION с ответившим, но не что это шлюз. Любое устройство в сети, ответившее на SSDP, становится «адресом, который сообщил сам роутер» в шаге 1 помощника (риск ввода пароля роутера на чужой странице). Исправить: `exact = true` только для роутера, которому человек нажал «Разрешить» (или из списка разрешённых); при «Не разрешать» и при смене сети `last_identify` сбрасывать; иначе показывать догадку `ACC_GW_GUESS`. Тесты на все три случая.
3. **Low. Зависшие потоки DNS.** `echo.rs` (около 415-429): каждая проба по имени сервера запускает поток DNS; по 5 с ожидание обрывается, поток остаётся, повторные нажатия копят потоки. Исправить: не больше одного разрешения имени одновременно (новое ждёт или получает `Busy`). Тест.
4. **Low. Сервер на Windows:** `chervo-rendezvous-server/src/lib.rs` (около 252-256) пауза 5 мс на каждую ошибку `recv`; поддельные запросы от закрытых портов порождают ICMP и ошибки приёма. Исправить: ошибки вида «соединение сброшено» (ICMP port unreachable, WSAECONNRESET) пропускать без паузы; паузу оставить только для прочих ошибок.

## Принято без правок
- Low: quinn-udp 0.5.16 при EINVAL на `sendmsg` с `src_ip` выключает GSO/ECN у сокета (скорость, не утечка). Записать в T22 как остаточный риск.
- Low: подмена DNS по имени сервера равна «лгущему серверу». Записать в T22.
- Для сведения: обход VPN раскрывает настоящий IP серверу и провайдеру до предупреждения (решения В2/В3, в T22 есть).

## Не проверено ревью
GUI и охрана Р11 (вызов 3 ревьюится отдельно); весь workspace; cargo fuzz; Р-2 с sing-box; ошибочный `src_ip` на Windows; отвергает ли `chervo-token` частные адреса и порт 0 в `extra` у `create_invite_ext`.

# Ревью безопасности GUI 13д (коммит 52ce455; combine-security, 2026-11-18)

Critical и High нет.

## К исправлению (круг 2, GUI)
1. **Medium. Страж Р11 обходится через `model.rs`.** `crates/chervo-gui/tests/gated_node_actions.rs` (около 250-265): `src/model.rs` в белом списке мест, где может встречаться команда, но `model_violations` проверяет только четыре файла моделей. Ревьюер вписал `Command::EchoProbe` и `Command::ReachCheck` в ветку `Outcome::Snapshot` в копии, и страж прошёл. Исправить: убрать `model.rs` из списка, добавить контрольный случай.
2. **Low/Medium. Страж проверяет место создания команды, а не то, что ветку вызвала кнопка.** `access_progress()` (`access_model.rs` около 293) вызывает `update_access(AccessIntent::AccessCheck)` из обновления снимка; это допустимо по Р10.1 (только в стадии `Waiting` после «Попробовать автоматически»/«Разрешить» и при сохранённом сервере). Исправить: правило «намерения `GetIp`, `AddCreate`, `AccessAuto/Allow/Check/Done`, `EchoSave/Clear` создаются только в `screens/`», одно записанное исключение для `access_progress`; контрольный случай.
3. **Low. Обходы текстового стража:** псевдоним `use ... Command as C`, glob-импорт `ExternalMode::*`, указатель на метод без скобок, заголовок с «или» (`Probe | Without =>`). Закрыть, где это дёшево (запрет псевдонимов и glob-импортов этих типов в GUI, запрет `echo_probe` без скобок); остальное записать в T22.
4. **Low.** Связано с п.2 ревью ядра: «точно» только для роутера из списка разрешённых (передано builder в круге 1).
5. **Low (UX).** Ответ поиска роутера, запущенного из настроек, при открытом заново помощнике показывает вопрос в настройках; после «Разрешить» старый статус `Mapped` сразу даёт «Готово». Исправить: ответ поиска относится к тому месту, откуда начат; «Готово» только по новому статусу после «Разрешить».

## Для владельца
Фраза «пока строка пустая, программа ни к какому серверу не обращается» теперь видна только по «?»; на виду нигде не сказано, что сервер видит ваш настоящий IP (остаточный риск T22). Предложение: одна строка на виду в разделе «Связь через интернет».
