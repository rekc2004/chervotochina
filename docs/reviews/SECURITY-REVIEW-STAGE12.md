# Ревью безопасности этапа 12 (адреса и смена IP)

Автор: combine-security (opus/high), 2026-10-16. Diff `0507b1e..dce62bd`. Опоры: `docs/specs/stage-12-addr.md`, `docs/THREAT_MODEL.md`, `docs/OWNER_DECISIONS.md` (U6, Н6, стук 9б). Записано дирижёром со слов ревьюера (агент только читает).

## Итог
Critical и High нет. 2 Medium, 6 Low. Формат токена, разбор, порядок сохранения seq, чтение v1->v2 и путь стука A3 соответствуют спецификации.

## Находки
- **M1.** Флаг HINT ставит отправитель; IPv4-записи обновления без hint не истекают (`chervo-token/src/addr_update.rs:194-208`, `chervo-addr/src/book.rs:50-56,125-130`). Друг может навсегда направить наши попытки на любой адрес. Мера: на этапе 13 ограничение попыток на адрес назначения для всех источников и флагов, не только hint; по желанию сбрасывать записи AddressUpdate после N неудач до нового seq.
- **M2.** `usable_addrs`/`findability` работают и для Blocked/RevokedByPeer (`chervo-friends/src/book.rs:866-874`): после смены сети мы бы стучали заблокированному и раскрывали новый IP. Мера: для не-Active пусто, данные хранить для `unblock`. Отклонение builder отвергнуто.
- **L1.** Один лгущий друг (Н6) вытесняет наш рабочий адрес у других друзей: `merge_update` убирает прежние AddressUpdate (`chervo-addr/src/book.rs:44-69`, `own.rs:354-362`); правило «не рассылать при противоречии» даёт лгуну подавить верный отчёт (только отказ). Вариант: получатель сохраняет прежние не-hint записи, если обновление состоит только из hint. Внести в T2.
- **L2.** Решение 9 не реализовано: `IssuedAddrUpdate` не несёт PairId, `WrongPeer` сравнивает соединение только с парой от вызывающего (`chervo-token/src/addr_flow.rs:233,257`). Мера: PairId в выданном токене (`FriendBook::issue_addr_update`), проверка в обоих помощниках.
- **L3.** Получатель доверяет флагу SHORT_LIVED на IPv6 (`chervo-addr/src/book.rs:54`). Мера: при приёме `short_lived = addr.is_ipv6()`.
- **L4.** Порядок in-band: verify -> stale -> rate limit (`chervo-friends/src/book.rs:817-829`): повтор стоит проверки Ed25519. Дешевле: stale и лимит по непроверенному seq сначала (ведёт только к отказу). При `now < at` лимит отключается. Этап 13 должен переслать последнее обновление при следующем соединении (RateLimited игнорируется).
- **L5.** Страж U6 в6 покрывает только подпись: `LocalSnapshot`, `GatewayInfo`, `observe` принимают любой `SocketAddr`. Этап 13: `LocalSnapshot` только из `probe_route_sources()` и `local_addrs()`, плюс grep-страж. «Проверяет компилятор» в сводке владельцу преувеличено.
- **L6.** `reknock` не объединяет повторные вызовы (`chervo-transport-quinn/src/client.rs:174-200`): при дребезге интерфейса копятся задачи. Цели только аутентифицированные адреса (`registry.rs:108-117`).

## Отклонения builder
1. `usable_addrs` для не-Active: отвергнуто (M2). 2. Обрезка до 16 по старейшему `last_seen`: принято (старые типы записей не истекают в `prune` — мелочь). 3. Лимит in-band в памяти: принято. 4. Любая ошибка decode -> `BadAddrUpdate`: принято. 5. `merge_update` сохраняет Contact: принято.

## Ответы на вопросы
Наблюдаемый адрес мы не набираем, только публикуем как hint. Токен обновления может направить наши попытки (M1): одна Initial + стук на попытку, усиления нет. Отравить вид другого друга напрямую нельзя (подпись связывает signer||recipient), только косвенно через Н6 (L1). Перебор до 1024 друзей запускается только вставкой токена, по сети нет; стоимость не измерена.

## Не проверено
Таблицы IANA (сверены дирижёром отдельно), код этапа 13 (нет), стоимость перебора 1024, 1M fuzz, clippy, цикл 20x, rename и fsync каталога на Windows, отсутствие пакетов у probe, поведение `Handle::spawn` после остановки runtime, реальный NAT и IPv6.
