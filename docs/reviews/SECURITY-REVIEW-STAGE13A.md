# Ревью безопасности этапа 13а (свой клиент UPnP IGD)

Автор: combine-security (opus/high), 2026-10-17. Diff `960c203..e26aab0`. Опоры: `docs/specs/stage-13a-upnp.md`, `docs/OWNER_DECISIONS.md` «Этап 13а», `docs/reviews/SECURITY-REVIEW-STAGE08.md` п.1-3, `docs/reviews/SECURITY-REVIEW-STAGE13.md`, `docs/THREAT_MODEL.md`. Записано дирижёром со слов ревьюера (агент только читает).

## Итог
Critical и High нет. 1 Medium (обходит защиту Ambiguous), остальные Low. Разборщики прочные; при пустом списке роутеров ни одного пакета (`mapper.rs:498-504`).

## Находки
- **M1.** Хост в домашней сети одним поддельным датаграммом (источник = IP роутера, другой LOCATION) выкидывает настоящий роутер из выбора (`ssdp.rs:338-358`, тест `ssdp_select_drops_conflicting_location`) и, зная UDN роутера (GET описания, NOTIFY), остаётся единственным кандидатом. То же: >64 мусорных датаграммы (`net.rs:124-129`), >8 отвечающих IP, исчерпание бюджета описаний (`mapper.rs:295-317`). Так же через `identify()` пользователю подсовывается UDN самозванца (`mapper.rs:513-521, 273-284`) — долговременная опора. Остаток решения 4 спецификации («нужен молчащий роутер или подмена ARP») неверен. Мера (отказ по умолчанию): конфликт LOCATION у IP, достигнут предел датаграмм, >8 отвечающих, не оценённый до срока ответчик -> `Ambiguous`; поправить спецификацию 4(e) и правило `select`.
- **L2.** SOAP роутеру не из списка: `current` сохраняется после NotHomeNetwork/NoGateway/Ambiguous, `release()` и удаление шага 1 шлют GetSpecific/Delete на сохранённый адрес без повторной проверки UDN (`mapper.rs:356-382, 529-535, 643-649`); в чужой сети с той же адресацией запрос уходит постороннему. Мера: если роутер из списка не единственный кандидат — забыть `current` без отправки (аренда ≤ 1 ч уберёт) или перепроверить UDN.
- **L3.** Бессрочный проброс на запасном порту (после 718 роутер вернул lease 0) принимается как MappedPermanent и после сбоя не находится проверкой при старте (ищет только ext = P) (`mapper.rs:444-457, 603-605`). Мера: lease 0 без запроса при ext ≠ P — Delete и Failed.
- **L4.** Обновления могут перекрываться после таймаута (`gateway.rs:186-199`, `mapper.rs:621-629`); удаления берут свой бюджет 3 с вне общего срока (~28 с вместо 25). Мера: `try_lock` «занято» в `refresh`, удаления в пределах общего срока.
- **L5.** Остаток SSRF из ревью 8: до 8 GET за поиск на любой хост/порт/путь в сегменте (только при непустом списке, не чаще раза в 60 с). Мера: убрать `;` и `=` из допустимых символов пути.
- **L6.** Стенд: `tools/netns/stage13a.sh:95` `rmdir /etc/netns` на хосте; `STATE=/tmp/chervo-stage13a-state` (`:31`) — предсказуемый путь под root с `rm -rf`/`cp` и запуском скопированного бинарника от root (подмена другим пользователем). Мера: `mktemp -d`, убрать `rmdir`.
- **L7 (сведения).** Страж «239.255.255.250 только в limits.rs» ничего не ловит: `net.rs:39` пишет `Ipv4Addr::new(239,255,255,250)`. «Спрашивает при первой встрече» согласуется с «пустой список = ноль пакетов», только если этап 18 вызывает `identify()` по кнопке.

## Проверено, находок нет
Разборщики (без паник, без неограниченных выделений, O(n), кроме `select` ≤ 64³ и дедупликации desc ≤ ~680²; `<!`, сущности, `&#`, повторный `<?`, глубина, число элементов, дубли; Content-Length ≤ 6 цифр и ≤ 65536, Transfer-Encoding, 3xx, obs-fold; чтение ≤ 8 КиБ + 64 КиБ + 1; срок чтения от остатка). Control URL только на хост:порт LOCATION. Источник только Private, ответчик == хост LOCATION, привязка к своему IP, TTL 1 до connect. `release` удаляет только своё (клиент + порт + "udp"). 725 и согласие верны. Эпоха работает. Устаревшие результаты отбрасываются в `commit_gateway`. chervo-connect без сокетов и без зависимости от chervo-upnp.

## Не проверено
Fuzz 1M, clippy, CI; IP_TTL на SYN в Windows, настоящий multicast, miniupnpd, реальные роутеры; датаграмма, выкидывающая роутер, и поток (M1 — по чтению кода и тесту); тесты fake_igd, тексты, python в `row_spoof`, текст T16.
